# 通話に接続した周辺機能

業務処理は `core/api/{social,learning,events}.mbt`、wire DTO と JSON decoder は `core/shared/features.mbt` にある。native と比較用 Node が同じ処理を実行し、React は生成した JS / TypeScript 型を利用する。追加パッケージや依存バージョンの変更はない。フロントエンド内の旧モックデータと偽 token によるログインは廃止し、ローカル確認も `AUTH_MODE=development` の実 API を使う。

## フレンドとメッセージ

`friendships` は順序付けた 2 人の ID を主キーにする。申請者と受信者を区別し、受信者だけが承認・見送り、申請者だけが取消できる。双方から同時に申請しても自動的には承認しない。見送り・取消後は再申請可能。承認済みの 2 人だけがメッセージを読み書きでき、名前の変更や重複に左右されない `/message/:friendId` を使う。

メッセージは最大 2,000 文字で保存し、`(sender_id, request_id)` の UNIQUE で並行再送を集約する。同じキーで内容・相手を変えると 409。最新 50 件と `before/:id` のカーソルで古いメッセージを取得する。送信済み本文は React が文字列として表示し、HTML として解釈しない。既読操作は本人宛ての行だけを変更する。

`/friendrequest` は実際の通話履歴から候補を作り、名前での検索も提供する。固定 ID の候補は廃止した。申請・承認の更新、メッセージの到着は画面の再読込なしに反映される。

## 永続通知と更新通知

フレンド申請・承認、随時通話への招待、イベントの相手決定、メッセージを `notifications` に保存する。元の書込みと同じ transaction に含め、イベントキーで重複を防ぐ。`GET /notifications` は本人宛ての最新 100 件、未読総数、サーバー時刻を返す。既読操作も本人の通知だけを対象にする。

`/activity` は初回メッセージの Bearer token と有効なユーザーを検証する。送るのは `{"type":"refresh"}` だけで、本文や他のユーザーのデータは含まない。画面が認証付き HTTP で保存済みデータを取得する。通話 signaling 用 `/ws` と独立しており、ICE/SDP の処理に DB アクセスを増やさない。

認証は 5 秒、初回入力は 8 KiB、送信待ちは 256 KiB、heartbeat は 30 秒。画面内では 1 接続を共用し、切断時は最大 30 秒の間隔で再接続する。再接続・タブの再表示と、表示中の 60 秒間隔で DB の状態を読み直し、commit 後のプロセス停止で更新通知だけが失われた場合も回復する。サーバー時刻と往復時間の中点から表示用の時計ずれを補正し、整数ミリ秒で共通時計へ渡す。

これはアプリを開いている間の通知である。ブラウザを閉じた状態での OS Web Push、メール通知は実装していない。複数サーバー間の即時 fan-out も未実装で、現在は単一サーバーでの稼働を前提とする。

## 実績と本人の振り返り

`GET /stats` は終了済みの会話から通話数・イベント／随時の内訳・相手の人数・累計時間・振り返り数を集計する。キャンセルした会話や未終了の会話は数えない。実績の達成状況もこの集計に基づく。架空の参加回数・常に「初回達成」と表示する画面は廃止した。

既存の満足度・感想・学んだ表現に加え、6 問の選択式回答を会話 ID と本人 ID に紐付けて保存する。通話相手からも読み取れない。`/sessionfeedback?conversation=:id` から記録でき、ID のない旧 URL は会話履歴へ案内する。

保存した感想・学んだ表現を、本人がボタンを押したときだけ外部 AI に送ってアドバイスを作る。録音・文字起こしはなく、音声や会話能力を評価したという表示はしない。`OPENAI_API_KEY` と任意の `OPENAI_MODEL` を設定する。未設定なら 503 になり、通常の振り返り保存は利用できる。`OPENAI_BASE_URL` は互換 API / ローカル試験用で、既定値は `https://api.openai.com/v1`。

生成結果は本人だけのデータとして保存する。同じ保存内容には既存の結果を返し、内容を編集したら古いアドバイスと表示する。生成待ちの間に感想が変わった場合、古い入力で作った結果を新しい内容の結果として保存しない。外部 AI の実サービスは呼ばず、ローカル HTTP fixture で入力範囲・応答・並行編集・不正応答を検証している。

## イベント参加と期限

`/events` は登録済みの参加ビットとマッチング状態を表示し、各ラウンドの参加・不参加を保存する。ホームの次回予定は自分が参加登録したイベントから選ぶ。管理画面は作成済みのイベント、参加者、マッチングの実行、各ラウンドの相手決定／待機を表示する。参加者の確定と公開は既存の transaction と unique 制約で守り、公開の再実行は 409。

イベント通話は両者の接続で保存された開始時刻から 300 秒。両 runtime が永続した状態を約 1 秒間隔・最大 100 件ずつ調べ、同じ会話ロックと revision の検査を使って終了させる。サーバー停止中に期限を過ぎた会話も再起動後に終了し、保存する終了時刻は開始 + 300 秒。参加者が期限後に手動終了した場合も同じ時刻に収束する。ブラウザを閉じてもこの処理は進む。DB 障害時は再試行するため、厳密なリアルタイム実行を保証するものではない。随時通話には期限を付けない。

## 移植用 DB の更新

`npm run db:migrate` で新しい表と期限検索用 index を追加する。migration 3 は旧 `friends` の相互 FRIEND だけを承認済みにし、片方向は申請中へ移す。どちらかの BLOCKED は維持する。古い表は残し、再実行で通知や関係を重複作成しない。この更新は移植先 repo の schema 専用であり、元の Ent DB の移行ではない。

## 検証

`tests/features.test.mjs` を JS/native の両方で実行する。承認前の送信拒否、申請の再送・見送り・取消、受信者以外からの操作拒否、通知の宛先、メッセージの再送・ページング・既読、集計、振り返りの非公開性、AI 待機中の編集、イベント参加ビット、ブラウザなしの期限終了を確認する。DB 更新は一時 DB で旧データから検証する。

Playwright では 2 ユーザー間の申請と承認、画面再読込なしのメッセージ配信、再読込後の保存内容、通知、管理画面での相手公開、選択回答の保存を確認する。既存の実 RTP 音声・再接続・終了試験も両 runtime で続ける。
